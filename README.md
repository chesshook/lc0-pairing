# LC0 Dual-T4 Kaggle Pairing

This project has a **two-notebook Kaggle setup**. Since a brand-new Kaggle runtime has no previously compiled LC0 binary or BT4 network, do not run the legacy `cache_export.py` first. Start with `bootstrap_cache.py` in the one-time Builder notebook, save its output files, and then use those saved files in the Server notebook.

GitHub stores only small source files and the public discovery pointer. It does **not** store LC0 binaries, BT4 weights, or either secret.

## Files in this repository

- `bootstrap_cache.py` — first-time clean-start build: installs build tools, clones LC0 v0.32.1 with its required submodule, compiles the CUDA backend for T4 compute capability 7.5, downloads and verifies BT4-it332, downloads cloudflared, smoke-tests the dual-GPU UCI engine, and writes the cache to `/kaggle/working/lc0-dual-t4-cache`.
- `cache_builder_cell.py` — short, Git-blob-SHA1-verified one-cell launcher for the Builder notebook.
- `lc0_kaggle_server.py` — persistent UCI/HTTP service that consumes the saved cache, starts one LC0 process, exposes a bounded authenticated JSON analysis API, launches a Cloudflare Quick Tunnel, and updates `hooker.txt`.
- `kaggle_final_cell.py` — Git-blob-SHA1-verified one-cell launcher for the Server notebook.
- `hooker.txt` — public discovery pointer. Starts at `OFFLINE`, then contains the currently active Quick Tunnel URL.
- `requirements.txt` — Python dependency pin.
- `cache_export.py` — optional legacy exporter for a session that already has the previously compiled LC0 and weights at the old validation paths. **Do not use this for a clean Kaggle runtime.**

## Stage 1 — one-time Builder notebook (do this first)

1. Open Kaggle and create a new notebook named `LC0 Dual T4 - Cache Builder`.
2. In Settings / Session options, choose **Accelerator: GPU T4 x2** and **Internet: On**.
3. Do not add any Kaggle Secrets for this notebook.
4. Add one Code cell and paste the complete content of `cache_builder_cell.py` from this repository.
5. Run that cell once and allow it to finish. It clones the pinned LC0 v0.32.1 source with its required submodule, builds native CUDA FP16 support using `-Dcc_cuda=75` (T4 compute capability 7.5), downloads the official BT4-it332 network, validates its exact byte size and SHA256, downloads cloudflared, and performs dual-T4 UCI smoke tests.
6. Do not interrupt the build. The expected final message is `CACHE BUILD COMPLETE`. The output folder is `/kaggle/working/lc0-dual-t4-cache`; it contains `lc0`, `BT4-it332.pb.gz`, `cloudflared`, and `manifest.json`.
7. Confirm the four files are visible under the notebook's **Output** tab.
8. Save a notebook version with output files enabled. In the Save Version dialog, choose **Quick Save** and open **Advanced Settings**; enable saving output files for Quick Saves. This preserves the output already generated by the interactive cell without rerunning the expensive build. Do not choose Save & Run All for this preservation step, because that starts a clean run and repeats the build.
9. Open the saved Builder version and confirm its Output Files include the `lc0-dual-t4-cache` folder.

Kaggle supports reusing notebook output files through **Input → Add Input → Notebook Output Files**. Its current notebook docs describe up to 20 GB of saved notebook output and T4 x2 as two Tesla T4 GPUs with four CPU cores and 29 GB RAM. Kaggle's documented GPU session ceiling is 12 hours.

## Stage 2 — Server notebook (repeat this after Kaggle restarts)

1. Create a second notebook named `LC0 Dual T4 - Server`.
2. Set **Accelerator: GPU T4 x2** and **Internet: On**.
3. Open **Input → Add Input → Notebook Output Files**, search for `LC0 Dual T4 - Cache Builder`, select its saved output version, and add it. Pin to latest only if you expect to intentionally publish updated cache versions later; otherwise the fixed saved version is fine.
4. In **Add-ons → Secrets**, create the five Secrets below and enable each for this Server notebook.
5. Add one Code cell, paste the complete content of `kaggle_final_cell.py`, and run it.
6. The cell fetches only the small server source file and verifies its Git blob SHA1 from this repository, validates it, installs `python-chess` only if needed, then starts the service.
7. Wait for `LC0 DUAL-T4 SERVICE ONLINE`. Confirm the printed base URL and `/health` URL. The GitHub `hooker.txt` file should then be updated from `OFFLINE` to the new Quick Tunnel URL.
8. Keep this cell running while using the service. Interrupt it to request cleanup and publish `OFFLINE`.

### Kaggle Secrets (Server notebook only)

| Secret | Value |
|---|---|
| `GITHUB_TOKEN` | Fine-grained GitHub PAT restricted to this repository, Contents: Read and Write; Metadata: Read-only |
| `GITHUB_REPO_OWNER` | `chesshook` |
| `GITHUB_REPO_NAME` | `lc0-pairing` |
| `GITHUB_BRANCH` | `main` |
| `ENGINE_API_TOKEN` | Separate randomly generated bearer token |

Generate the engine token locally, for example with `python -c "import secrets; print(secrets.token_urlsafe(32))"`. Store it privately in Kaggle Secrets and a password manager. Never commit it or paste it into chat.

### What the Builder does technically

- Clones `https://github.com/LeelaChessZero/lc0.git` at tag `v0.32.1` with recursive submodules.
- Installs Meson, Ninja, a C++ build toolchain and zlib headers.
- Builds release mode with native CUDA enabled, `-Dcc_cuda=75`, cuDNN off, ONNX off and unnecessary CPU BLAS/test targets off.
- Downloads `https://storage.lczero.org/files/networks-contrib/BT4-1024x15x32h-swa-6147500-policytune-332.pb.gz`.
- Verifies BT4 size = `382645315` and SHA256 = `e6ada9d6c4a769bfab3aa0848d82caeb809aa45f83e6c605fc58a31d21bdd618`.
- Downloads the small `cloudflared` executable, runs its version check and writes hashes into `manifest.json`.
- Starts LC0 once with `--backend=demux` and `--backend-opts=backend=cuda-fp16,(gpu=0),(gpu=1)`, then verifies legal moves.
- Removes temporary source/build intermediates after successful tests so only the four runtime files remain in the output folder.

### What happens after a runtime restart

| Component | Behavior |
|---|---|
| LC0 executable | Reused from saved Notebook Output Files |
| BT4 weights | Reused from saved Notebook Output Files |
| cloudflared binary | Reused from saved Notebook Output Files |
| LC0 compilation | Not repeated |
| BT4 download | Not repeated |
| Small Python server source | Fetched from GitHub (about 20 KB) |
| CUDA setup and BT4 GPU memory load | Repeated once per new runtime |
| Quick Tunnel URL | New URL generated and published to GitHub |

The output cache is read-only when attached as Input. The server copies the two executable tools into writable `/kaggle/working/lc0-runtime-bin`, but reads the BT4 weights directly from the mounted cache and does not copy the 383 MB file.

## API contract

Public discovery URL:

`https://raw.githubusercontent.com/chesshook/lc0-pairing/main/hooker.txt`

- `GET /health` — public readiness, LC0 identity and GPU list.
- `POST /v1/analyze` — authenticated analysis.
- Header: `Authorization: Bearer <ENGINE_API_TOKEN>`.
- Example JSON: `{"fen":"rnbqkbnr/pppppppp/8/8/8/8/PPPPPPPP/RNBQKBNR w KQkq - 0 1","movetime_ms":1800}`.

The API returns UCI/SAN best move, PV, score, depth, nodes, NPS and elapsed time. Inputs are bounded and the service does not expose arbitrary UCI commands or shell execution. Overlapping requests receive HTTP 429 instead of building a stale queue.

## Limitations

Kaggle GPU sessions are finite and may be interrupted. Cloudflare Quick Tunnels are testing infrastructure with changing hostnames and no uptime guarantee. The phone must treat `hooker.txt` as a discovery hint, validate `/health`, and handle `OFFLINE`, stale endpoints, timeouts and HTTP 429. A forced runtime kill may prevent the server's shutdown handler from updating the pointer, so the client must always check health before analysis.
